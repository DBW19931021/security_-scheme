# ADR-0023：工程文档可视化与双向链接规则

- 状态：accepted
- 日期：2026-07-28
- 决策人：项目负责人
- 适用范围：`security_-scheme`中的OpenSpec、正式详设、架构/接口专题、ADR、Source Card、计划、测试设计和Evidence说明

## 背景

当前主详设已经覆盖完整软件设计，但复杂启动链、内存布局、Owner转换和失败路径主要依赖长篇文字或表格；部分引用只写Source ID、ADR编号或文件名，读者无法立即判断文档类型，也不能直接跳转。专题文件与主详设之间也缺少统一反向入口。

## 决策

1. 对三个及以上步骤、分支、参与者、状态或内存对象的关系，文档应优先增加Mermaid流程图、时序图、状态图、数据流图或内存示意图；图示必须表达规范关系，不能只作装饰。
2. 图示不能取代精确表格、字段offset、状态转换条件、错误语义和文字约束；图与正文冲突时必须立即修正文档。
3. 引用仓库内已有文档时，必须使用“可辨识名称 + 文档类型/用途 + 可点击相对链接”，不能只写裸文件名、裸Source ID或裸ADR编号。
4. 主详设引用专题/ADR/Source/Evidence时，目标文档必须提供返回主详设的反向链接；专题文档引用其他规范文档时也应建立对等返回入口或明确`Referenced by`。
5. 原始资料由Source Card作为受控导航入口；引用者应写明资料名称、类型、Source ID和状态，避免读者只能看到无法理解的编号。
6. 新增或修改Markdown时必须检查本地链接有效性；正式主文档应提供集中“资料导航与双向链接”章节。

## 影响

- OpenSpec项目约束和change模板采用本规则。
- 主详设补充多类图示和集中导航。
- 现有关键专题、接口和Source Card增加返回主详设的链接。
- 本ADR不改变安全行为、ABI或代码实现。
