# 评审目的

> **历史评审说明（2026-09-01）**：本文保留W0阶段事实与裁决过程；其中Manifest目标格式已由ADR-0030/0033替代。当前包为Header[1024]+Code[Code_Size]，offset1008为LE64 load、offset1016为LE32 Header CRC32、offset1020为4B零reserved，entry=load，身份/Profile/policy来自typed-stage registry。

本评审包是开发计划 W0 的第一个正式出口。目标不是立即选择所有硬件参数，而是把以下三类内容分开：

1. 可依据 SRC-0016/SRC-0017 和 CE-SEC-001/002 直接进入首轮详细设计评审的安全不变量。
2. 可以先冻结接口形状、但数值/平台参数仍待输入的内容。
3. 必须由负责人裁决、不能由 Codex 或现有代码代替决定的冲突和产品行为。

评审通过只会使首批任务进入 `ready_for_openspec`；不会自动授权修改 `gsp-pmp-rmp-omp` 或 `baremetal`。

当前评审状态：W0-R1-01～04、W0-R1-06～11已批准；W0-R1-05当前不采用。D1～D3均已关闭：自检采用Bootloader位图，Die1独立记录Measurement实例；W0原地址domain方案已被2026-07-28最终裁决替代，当前全链路只使用baremetal System Address且不存在Local/System映射。批准记录见[ADR-0003](../../decisions/ADR-0003-w0-approved-principles-and-self-test-bitmap.md)和[ADR-0004](../../decisions/ADR-0004-die1-measurement-gsp-address-and-handoff-scope.md)。

本文件保留为已完成的W0首轮原则评审记录。当前`TASK-SEC-SOC-FW-001`的正式详设评审入口已转为[SOC安全固件首轮详设评审包-启动链与核心合同](SOC安全固件首轮详设评审包-启动链与核心合同.md)；新发现的OPEN-CONFLICT-004/005不反向改写本轮已批准原则。

# 需要负责人裁决的项目

## D1：OPEN-CONFLICT-001 自检位图（已关闭）

Vendor 已回复并由负责人确认：当前交付采用 Bootloader 定义，Host 定义错误。Adapter 保留 raw bitmap，并按 Bootloader 映射解释：bit18/`0x40000`=`TRNG`；bit19/`0x80000` 在当前 Bootloader 表中没有已确认含义，保持 unknown/reserved，不解释成 TRNG。原始 Vendor 回复材料后续仍需按 Source 流程补录，但不再阻塞当前位图设计和用例 093 的下一版本更新。

## D2：OPEN-CONFLICT-002 Die1 Measurement（已关闭）

负责人批准推荐Option A：

- 内部 measurement table 始终保留 Die1 实际加载实例，使用 `die_id=1`；即使 hash 与 Die0 相同也能证明该实例已 release。
- SPDM 是否逐条返回可由 profile 决定，但聚合时必须有可验证的 Die1 release/status 表达，不能完全丢失实例状态。

该规则进入ADR-0004。用例107不再阻塞；v0.2保持不变，v0.3高亮更新Expected。

## D3：OPEN-CONFLICT-003 GSP 地址域（已关闭）

2026-07-22曾批准Option A；2026-07-28最终裁决已取代当时的domain/转换方案：

- Manifest `load_addr`/`entry_addr`、C908、loader、linker和eHSM共享descriptor统一使用baremetal `MANAGEMENT_NOC_S9_SRAM_BASE/SIZE` System Address；
- 不定义Local/System映射，旧`0x1000_0808_0000/0x1010_0808_0000`和local/remap输入一律拒绝；
- eHSM/FMC等master的实际System Address可达性、最终PMA、barrier可见性、data clean/invalidate零调用和Firewall仍通过RTL/EMU验证，但不再开放地址视图选择。

后续实施不得沿用现有packager/test中的旧080x Expected；OPEN-CONFLICT-006只继续阻断精确Region offset/容量、PMA和Firewall，不阻断System Address语义。

## D4：失败终态

“失败不可到达下一级”不变量继续有效。ADR-0006已进一步冻结职责：security stage只记录、阻断、清零并上报；halt/wait/restricted service由stage详设，watchdog/eHSM/system reset或隔离由RAS策略决定和执行：

| Stage/失败 | 当前最低要求 | 待裁决终态 |
|---|---|---|
| BootROM eHSM/FMC 失败 | 不跳 FMC，保存最小诊断 | halt / watchdog reset / OOB wait |
| FMC 验证 GSP 失败 | 不 release GSP；保持最小安全控制面仅在软件方案允许时 | wait redownload / reset / OOB |
| GSP 验证某 Runtime 失败 | 不 release 该 Runtime；依赖项全部阻断 | 局部受限服务 / 整机 reset / recovery |
| 不可逆 command timeout | 禁止盲目重试，先查询实际状态 | query/reconcile API 和人工恢复 |
